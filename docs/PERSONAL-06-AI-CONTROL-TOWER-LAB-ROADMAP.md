# Personal AI Control Tower Lab Roadmap

## Goal

Use the personal environment to learn AI Control Tower as an operational tool,
not merely as a governance concept.

## Stage 1 — Inventory

- [ ] Open AI Control Tower.
- [ ] Inventory currently visible ServiceNow AI assets.
- [ ] Identify Microsoft Copilot connection/discovery state.
- [ ] Record any unmanaged/discovered assets.
- [ ] Identify ownership/lifecycle fields.
- [ ] Capture what AICT can and cannot discover automatically.

## Stage 2 — Ownership

For one personal AI capability:

- [ ] Create/link an AI asset where appropriate.
- [ ] Assign yourself as lab asset owner.
- [ ] Record purpose.
- [ ] Record platform/provider.
- [ ] Record capability ID.
- [ ] Record repository reference.
- [ ] Record risk/autonomy level.
- [ ] Record support/disable method.

## Stage 3 — Copilot / external AI

- [ ] Review how Copilot assets/context appear in AICT.
- [ ] Validate connection/authentication.
- [ ] Compare discovered metadata with actual Copilot configuration.
- [ ] Record gaps.
- [ ] Test reconciliation of known vs discovered asset.

## Stage 4 — Lifecycle

Move a disposable lab asset through:

```text
Idea
→ Assess
→ Build/Test
→ Deploy in lab
→ Monitor
→ Retire
```

Document what AICT records at each stage.

## Stage 5 — Value / utilization

For one capability:

- [ ] capture usage;
- [ ] capture assist/token/platform cost where available;
- [ ] estimate time saved;
- [ ] record quality/acceptance;
- [ ] distinguish capacity from hard-dollar savings;
- [ ] compare AICT metrics to your own run traces.

## Stage 6 — Incident / failure

Create a safe simulated failure:
- broken token;
- unavailable API;
- bad AI output;
- failed tool call.

Practice:
- identifying the asset;
- tracing the failure;
- disabling the capability;
- recording an issue/case;
- restoring service;
- updating an eval.

## Stage 7 — Portfolio review

Review:
- what AI exists;
- what is duplicated;
- what has no value;
- what costs more than expected;
- what should be kept, optimized, or retired.

## Outcome

You should be able to explain both:

1. how AI Control Tower works technically;
2. how it fits into an enterprise operating model without claiming to own enterprise AI governance.
