# Personal Lab Operating Model

## One-person team model

You may wear all of these hats:

```text
Product Owner
Platform Owner
Architect
Engineer
Reviewer
Security Reviewer
Tester
Operations
```

The point is not organizational separation.

The point is learning to **think through each responsibility separately**.

## Lightweight lifecycle

```text
Idea
 ↓
Experiment card
 ↓
Context / architecture
 ↓
Build
 ↓
Test / eval
 ↓
Review
 ↓
Use in DEV
 ↓
Measure
 ↓
Keep / Refactor / Retire
```

## Definition of done

A meaningful lab capability should ideally have:

- purpose;
- architecture note;
- source code/config;
- test/eval;
- run example;
- README;
- known limitations;
- next step.

That is enough governance for most personal experiments.
