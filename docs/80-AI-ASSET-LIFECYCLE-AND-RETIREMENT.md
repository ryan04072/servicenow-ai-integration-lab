# AI Asset Lifecycle and Retirement

## Lifecycle

```text
Demand
→ Onboard
→ Assess
→ Build & Test
→ Pre-deployment approval
→ Deploy
→ Monitor
→ Measure value
→ Change/reassess
→ Retire
```

## Material-change triggers

Re-assess for:
- new model/provider;
- new data classification;
- new write tool;
- production access;
- major behavior change;
- autonomy increase;
- new business purpose;
- material incident;
- new regulatory requirement.

## Retirement

When an asset is retired:
- disable triggers;
- remove/revoke credentials;
- remove tool permissions;
- remove connectors if unused;
- archive evidence;
- update AI inventory;
- update capability/agent registry;
- remove/redirect user entry points;
- apply data/trace retention policy;
- close vendor/licensing cost where applicable;
- communicate replacement where relevant.

Periodically identify inactive assets with active credentials, orphan owners,
unused agents, unmanaged assets with production permissions, and duplicates.
